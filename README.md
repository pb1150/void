

### 1. 完整流程的 UE5 C++ 项目架构

- 使用 **Unreal Engine 5.4**，以 **C++ 为核心、Blueprint 为扩展** 的混合开发模式：核心系统（战斗、刷怪、数据结构）写在 C++，表现与调试逻辑通过蓝图补充。
- 项目全程使用 **Git** 管理版本，包含分支管理、提交信息规范等，方便回滚与代码审查，符合团队协作开发习惯。
- 按功能模块拆分代码结构（AbilitySystem / Game / Character / UI / Library 等），便于维护和扩展，避免“巨型脚本”式耦合。

---

### 2. Gameplay Ability System（GAS）战斗框架

- 基于 **GAS** 自定义 `AttributeSet`，管理生命值、魔力、护甲、暴击率等战斗属性，为后续平衡和数值扩展打好基础。
- 编写自定义 **GameplayEffect** 与 **MMC（Mod Magnitude Calculation）**，例如格挡几率计算类，用于根据护甲、Buff 等动态计算最终数值，而不是写死在蓝图中。
- 技能系统支持 **冷却、资源消耗、Buff / Debuff、持续伤害/治疗** 等效果，参数由数据驱动，方便策划通过配置调整而无需改代码。
- 能力逻辑主要在 C++ 中实现，触发条件、动画蒙太奇、特效等通过蓝图拼接，实现 **“底层稳定 + 表现灵活”** 的结构。

---

### 3. 敌人 AI 与战斗系统

- 敌人具备基础感知与行为逻辑：在一定范围内发现玩家后，使用 AI MoveTo 追击，脱战后恢复巡逻或待机。
- 支持多种敌人类型（如近战/远程等，可拓展），通过统一的战斗接口/基类复用公共逻辑，便于后续快速增加新怪物。
- 实现 **受击反馈与死亡逻辑**：包含受击时的数值计算、动画触发、无效攻击过滤（如攻击已死亡目标）等。
- 在敌人死亡时，通过 C++ 函数（如 `SpawnDropItems`）生成掉落物，掉落规则可配置，方便日后拓展装备、经验球、随机奖励等系统。

---

### 4. 关卡与怪物生成流程

- 使用自定义的 `AEnemySpawnPoint` 作为敌人生成点，通过标签/权重等方式控制不同区域刷怪类型与数量。
- 在 `GameMode` 中集中管理刷怪逻辑：根据当前存活敌人数、总击杀数等数据来控制刷怪节奏，避免场上怪物过多或过少。
- 当玩家击杀数量达到关卡要求后，由 `GameMode` 生成 **传送装置 / 下一关入口（Transmitter）**，形成“刷怪 → 解锁出口 → 进入下一关”的完整循环。
- 整套系统以 **数据驱动 + 状态判断** 为核心，后续可以很容易接入 PCG 生成的关卡或不同难度的关卡配置。

---

### 5. 存档系统与运行数据统计

- 通过 `GameInstance` / `SaveGame` 记录关键通关信息，例如：总运行时间（基于 `GetRealTimeSeconds` 计算）、累计击杀数等，为后续战绩结算、排行榜或 Roguelite 统计打基础。
- 设计了记录“**被哪种敌人击杀**”的机制，可以在死亡结算界面展示死亡来源，增强反馈感，同时为后续数据分析提供依据。
- 存档结构预留扩展空间，可进一步记录玩家构筑、选择的天赋、关键事件等，用于实现多周目或永久升级系统。

---

### 6. UI 系统与 DataAsset 驱动的配置

- 使用 UMG + WidgetController 搭建 UI 系统，包括：技能栏、血条、技能选择界面、提示信息等，逻辑与显示分离，方便重构与换皮。
- 通过 `DataAsset` 存储角色、技能、敌人以及数值相关的配置（如冷却时间、消耗、图标、描述等），使大量设计工作可以通过改表完成，而不用频繁改动 C++。
- UI 交互支持诸如 **技能槽鼠标悬停显示详情、点击触发、按钮音效播放** 等细节，提升可用性与手感。
- 整体 UI 架构围绕“**数据驱动 + 控制器分发事件**”的思路设计，便于将来接入本地化、多语言与不同平台的 UI 方案。
